# MdSight 仕様

`AGENTS.md` の「作業の進め方」に従って読む。作業に関係する節だけを読めばよい。

## Neovimプラグイン（Lua）

DO

- `require("mdsight").setup({ bin = "<実行ファイルのパス>" })` で設定する。設定項目は `bin` だけにする。`bin` を省略したときは、プラグインのディレクトリ（リポジトリのルート）の直下にある `mdsight` を使う
- 次の2つのコマンドを提供する
  - `:MdSight`：現在のバッファとウィンドウを対象にする。プレビューが開いていなければアプリを起動し、開いていれば対象を切り替える（本文もすぐに送る）
  - `:MdSightClose`：アプリに終了を通知する。応答がなければプロセスを終了させる。Lua側の状態、autocmd、タイマーもすべて解放する
- 対象にできるバッファを「`buftype` が空で、ファイル名があり、`filetype` が `markdown` のもの」に限る。それ以外なら理由を `vim.notify` で表示して、何もしない
- RPCソケットには `vim.v.servername` を使う。空であれば `vim.fn.serverstart()` で作成する
- アプリは `vim.system` を使い、引数の配列（`--nvim <socket> --token <起動トークン>`）で起動する。プロセスが終了したら、Lua側の状態を解放する
- 対象を設定するたびに「対象世代」を1増やす
- 本文を送るたびに「版」を1増やす
- 本文の送信：対象バッファの `TextChanged` / `TextChangedI` を受けて、200msのデバウンス後に全行を送る。対象を設定したときは、デバウンスせずにすぐ送る
- カーソル位置の送信：対象ウィンドウでの `CursorMoved` / `CursorMovedI` を受けて、50ms間隔のスロットル（最新の値を送る）で行番号を送る。直前に送った行と同じなら送らない
- 対象を設定したときは、スロットルを待たずに、その時点のカーソル行もすぐ送る
- 対象ウィンドウが閉じたら（`WinClosed`）、カーソル位置の送信を止める
- 対象ウィンドウ内での移動への追従：`BufEnter` / `BufWinEnter` を受けて、対象ウィンドウに表示されているバッファが対象バッファと違えば、次のように扱う。リンクを辿る要求（`open`）の処理中は、追従しない
  - そのバッファが「対象にできるバッファ」なら、それを新しい対象にする（対象世代を1増やし、本文とカーソル行をすぐ送る）。対象ウィンドウは変えない
  - 条件を満たさなければ、対象を変えず、通知もしない
- 対象ウィンドウに対象バッファが表示されていない間は、カーソル位置を送らない。対象バッファが再び表示されたら、その時点のカーソル行をすぐ送る（対象世代は変えない）
- 対象バッファが削除されたら（`BufWipeout` / `BufDelete`）、削除の処理が終わった後（`vim.schedule`）に対象ウィンドウが有効かを調べる。有効なら、そのバッファのautocmdを外して本文の送信を止め、プレビューは最後の表示のまま、上の追従を待つ。無効なら、`:MdSightClose` と同じ処理を行う
- 検索の強調の送信：`SafeState` のたびに、次の値を前回送った値と比べ、どれかが変わっていれば `mdsight_search` を送る。アプリと接続していない間は送らない
  - 検索語（`getreg("/")`）、`v:hlsearch`、対象世代、版、現在の一致
- 一致は、`v:hlsearch` が 1 で検索語が空でないときだけ、`matchbufline()` で対象バッファの全行から求める（検索語、`v:hlsearch`、対象世代、版のどれかが変わったときだけ求め直す）。それ以外のとき、検索語が正しくないとき、対象バッファがないときは、一致を空にする
  - 大文字と小文字の扱いは、Neovimの検索と同じにする（`'ignorecase'` と `'smartcase'` に従う）
  - 送るのは、先頭から1000件までにする
- 現在の一致は、対象ウィンドウが対象バッファを表示しているときだけ、カーソル位置を含む一致（なければ無し）とする
- ジャンプ要求を受けたら、1回の関数呼び出しの中で次のすべてを検証してから、`nvim_win_set_cursor(winid, {line, 0})` を実行する。検証に失敗したら、何もしない
  - 対象世代と版が、現在の値と一致すること
  - 対象ウィンドウが有効で、対象バッファを表示していること
  - 行番号が、バッファの行数の範囲内にあること
- ジャンプ先の行が折り畳まれていたら、`normal! zv` で開く
- ジャンプを実行したら、「直前に送った行」をジャンプ先の行に設定する（この結果として起きる `CursorMoved` を送らないため）
- リンクを辿る要求（`open`）を受けたら、1回の関数呼び出しの中で対象世代と版が現在の値と一致することを検証してから、対象ウィンドウで指定されたファイルを開く。開く前に、いまの対象のautocmdを外す。開いた後のバッファが「対象にできるバッファ」の条件を満たしていれば、それを新しい対象にする（対象世代を1増やし、本文とカーソル行をすぐ送る）。開けなかった場合や条件を満たさない場合は、理由を `vim.notify` で表示し、元の対象のままにする

DO NOT

- ファイルを読まない。`BufWritePost` やファイル監視も使わない（ただし、リンクを辿る要求を受けたときは、対象ウィンドウで指定されたファイルを開いてよい。下の「導入とヘルスチェック」の `build.lua` と `:checkhealth` は、プラグインのディレクトリの `src-tauri/Cargo.toml` を読んでよい）
- `nvim_win_set_cursor` にウィンドウ番号 `0` を渡さない
- 対象ウィンドウ以外のウィンドウでバッファを移動したとき、表示対象を自動で切り替えない
- アプリ側から任意のLuaコードを実行させる口を作らない。アプリから呼べるのは、`require("mdsight.rpc")` が公開する固定の関数（`register`、`jump`、`open`）だけにする

## 導入とヘルスチェック（Lua）

DO

- lazy.nvim では、`{ "tkrkmb/mdsight", version = "*", build = "build.lua", opts = {} }` だけで導入できるようにする。遅延読み込み（`ft`、`cmd`）は勧めない（読み込まれる前は `:checkhealth mdsight` が見つからないため）
- リポジトリのルートに `build.lua` を置く。lazy.nvim が導入と更新のたびに実行する
  - プラグインのディレクトリの `src-tauri/Cargo.toml` から版を読み、`releases/download/v<版>/` から、OSに合う `tar.gz`（macOSは `mdsight-universal-macos.tar.gz`、Linuxの x86_64 は `mdsight-x86_64-linux.tar.gz`）を取得する。それ以外のOSとCPUでは、理由を出して失敗する
  - 取得と展開には、`curl` と `tar` を `vim.system` で、引数の配列で実行する。一時ディレクトリに展開し、実行ファイルだけを、プラグインのディレクトリの直下に `mdsight` として置く
  - 失敗したら、理由を出して `error` で終える（lazy.nvim がビルドの失敗として表示する）。そのとき、すでにある実行ファイルは残す。成功したら、置いた実行ファイルの版を1行出す
- プラグインのディレクトリの直下の `mdsight` は、`.gitignore` に入れる（lazy.nvim の更新を妨げないため）
- `:checkhealth mdsight` を、`lua/mdsight/health.lua` で提供する。次の項目を調べ、それぞれ成功／警告／失敗を出す
  - Neovimが0.10以上であること
  - `setup` が呼ばれていること
  - 使う実行ファイル（`bin`、なければ既定の場所）が存在し、実行できること。なければ、lazy.nvim の `:Lazy build mdsight`、READMEの手動の手順、ソースからビルドしたときの `cargo tauri build --no-bundle` を案内する（版が違うときも同じ）
  - 実行ファイルの `--version` の版が、プラグインのディレクトリの `src-tauri/Cargo.toml` の版と一致すること（`Cargo.toml` がなければ、調べなかったことを出す）
  - Linuxでは、実行ファイルに `ldd` を実行し、見つからないライブラリがないこと。あれば、その名前を並べ、WebKitGTK 4.1 の導入を案内する

DO NOT

- `:MdSight` などの通常の操作の中で、実行ファイルを取得しない（取得は `build.lua` だけで行う）
- `build.lua` で、`tar.gz` の中の `lua/` などを、プラグインのディレクトリに展開しない

## RPC（NeovimとRustの間）

DO

- アプリは起動したらソケットに接続し、`nvim_get_api_info()` で自分のチャネルIDを取得する。その後、`nvim_exec_lua('return require("mdsight.rpc").register(...)', {token, chan})` を呼ぶ
- `register` はトークンを検証してチャネルを記録し、初期状態（対象世代、版、本文の行配列、文書の絶対パス、カーソル行）を返す
- Neovimからアプリへの通知は、`vim.rpcnotify(chan, name, payload)` で送る。通知の種類は次の4つに限る
  - `mdsight_content`：`{gen, version, path, lines, follow}`。`follow` は、対象ウィンドウ内での移動への追従で対象世代が変わった直後の送信だけ `true`、それ以外は `false`
  - `mdsight_cursor`：`{gen, line}`
  - `mdsight_close`：`{}`
  - `mdsight_search`：`{gen, version, matches}`。`matches` は、一致ごとの `{line, text, current}`（行番号、一致した文字列、現在の一致か）を、バッファでの出現順に並べた配列。空なら強調を消す
- アプリからNeovimへのジャンプは、`nvim_exec_lua('return require("mdsight.rpc").jump(...)', {gen, version, line})` で行う
- アプリからNeovimへのファイルを開く要求は、`nvim_exec_lua('return require("mdsight.rpc").open(...)', {gen, version, path})` で行う。`path` は絶対パス。戻り値の真偽で、開けたかどうかをアプリに伝える
- RPCが切断されたら、アプリを終了する

DO NOT

- HTTPサーバー、WebSocket、TCPでの待ち受けを作らない（例外は、下の「Rust」に書いた、スタンドアローンモードの前面化のためのUnixドメインソケットだけ）
- RPCの受信処理の中で、描画が終わるのを待たない。受け取ったらキューに渡してすぐ返す

## Rust

DO

- comrakで次の拡張を有効にする：table、strikethrough、tasklist、autolink、`math_dollars`、`header_ids`（プレフィックスは空文字）、footnotes、alerts、`front_matter_delimiter`（`---`）
- フロントマター（文書の先頭の `---` で囲んだYAML）は、GitHubと同じく表にして本文の前に出す
  - 最上位のキーを見出しの行に、値をその下の行に並べる。値がマッピングや配列なら、入れ子の表にする。キーと値はHTMLとしてエスケープする
  - 表には、フロントマターの行範囲を `data-sourcepos` として付ける（位置表とスクロール同期の対象にするため）
  - YAMLとして読めないとき、または最上位がマッピングでないときは、元のテキストをコードブロックとして出す
  - YAMLの解析には、クレートを1つだけ追加する
  - フロントマターの表への変換には、`cargo test` で動くテストを書く
- `render.sourcepos = true` を有効にする
- `render.unsafe_` を `true` にして生HTMLを受け付け、comrak が出力したHTML全体を `ammonia` でサニタイズする（生HTMLだけを切り出してサニタイズすることはできない。comrak は生HTMLを開きタグと閉じタグの細切れのまま出力するため）
  - 残すのは、comrak 自身が出力する要素と属性（`data-sourcepos`、見出しのID、脚注、アラート、タスクリスト、数式の目印など）と、生HTMLで次に挙げるものだけにする。スクリプト、スタイル、イベントの属性（`on*`）など、それ以外はすべて取り除く
    - `details`、`summary`（`open`）
    - `img`（`src`、`alt`、`width`、`height`、`align`）
    - `picture`、`source`（`srcset`、`media`）
    - `a`（`href`）
    - `br`、`kbd`、`sub`、`sup`、`ins`、`del`、`s`、`b`、`i`、`strong`、`em`、`code`
    - `p`、`div`、`h1`〜`h6`（`align`）
  - URLのスキームは、`http`、`https`、`mailto` と相対パスだけを残す
  - サニタイズには、`cargo test` で動くテストを書く（取り除くものと、残すもの、comrak の出力が壊れないこと）
- ```` ```mermaid ```` のブロックはcomrakで通常どおり出力し、フロントエンドで処理する
- 世代と版が最新の本文だけをHTMLに変換し、Tauriのイベントでフロントエンドへ送る。フロントエンドが最新の状態を取得するためのコマンドも用意する
- 画像のパスを解決するコマンドを用意する。入力は相対パスと版で、手順は次のとおり
  - 文書のディレクトリを基準にパスを解決する（パーセントエンコードのデコードも行う）
  - シンボリックリンクを実体のパスに解決する
  - ファイルが存在し、拡張子が png、jpg、jpeg、gif、webp、svg のいずれかである場合だけ、そのファイル単体をassetプロトコルのスコープに追加して、絶対パスを返す
- 画像パスの解決には、`cargo test` で動くテストを書く
- 起動引数が `--nvim <socket> --token <token>` ならNeovim連携モード、単一の位置引数（ファイルパス、`--foreground` を付けてもよい）ならスタンドアローンモードとして起動する。`--version` だけなら、`mdsight <版>`（版は `Cargo.toml` の値）を標準出力に1行書いて終了する。それ以外の引数の組み合わせはエラーを表示して終了する
- スタンドアローンモードでは、指定されたファイルを読み、GFMのHTMLに変換して表示する。ファイルが存在しないか、拡張子が `md`／`markdown` でなければ、エラーを表示して終了する
- スタンドアローンモードでは、ファイルを検証できたら、端末から切り離した子プロセス（別のプロセスグループ、標準入出力は捨てる）としてウィンドウを開き、コマンド自体はすぐに終了する。`--foreground` を付けたときだけ、切り離さずにそのまま動かす（切り離す子プロセスの起動にも、この引数と正規化済みの絶対パスを使う）。Neovim連携モードでは切り離さない
- スタンドアローンモードでは、開いているファイルを監視し、変更されたら読み直して表示を更新する。世代は「開くファイルが変わるたび」、版は「読み直すたび」に1増やす
- スタンドアローンモードで、読み直しに失敗したときや、ファイルの監視を始められなかったときは、その問題をTauriのイベントでフロントエンドへ知らせる（標準エラー出力にも書く）。読み直せたとき、または別の文書を開いて監視を始められたときは、問題を取り消す。フロントエンドが起動直後に現在の問題を取得するためのコマンドも用意する
- 文書内の相対パスで、拡張子が `md`／`markdown`（末尾に `#見出し` が付いていてもよい）のリンクを開く要求を受けたら、いまの文書のディレクトリを基準にパスを解決する（手順は画像の解決と同じ：パーセントデコード、シンボリックリンクの解決、存在の確認）。解決できたら、そのファイルを新しい文書として開く。Neovim連携モードでは、Rustから `rpc.open` を呼んでNeovim側にも同じファイルを開かせ、対象を切り替えさせる
- リンクで開いた文書の履歴を、戻る／進むで辿れるようにする。戻る・進むとも、開き直す手順は上と同じ（スタンドアローンモードならファイルを読み直す、Neovim連携モードなら `rpc.open` を呼ぶ）。Neovim連携モードで `rpc.open` が失敗を返したら、履歴を動かさない
  - 履歴の各項目には、文書のパスと一緒に、その文書で読んでいた位置（フロントエンドの「画面の上端付近にあるブロックのソース行と、画面内でのオフセット」）を持たせる。リンクを開く・戻る・進むのコマンドは、フロントエンドからいまの位置を受け取って、離れる文書の項目に記録し、移動先の項目に記録されていた位置（なければ無し）を返す
  - 履歴に位置を持たせる処理には、`cargo test` で動くテストを書く
- 戻る／進むそれぞれを辿れるかどうかを、フロントエンドが取得できるコマンドを用意する
- Neovim連携モードで、`rpc.open` 以外の理由（`:MdSight` による対象の切り替えなど）で対象世代が変わったら、リンクの履歴を空にする。そのうち `mdsight_content` の `follow` が `false` のときだけ、窓が隠れていれば前面に出す（対象ウィンドウ内での移動への追従では前面に出さない）。前面に出すときはフォーカスを移さない（Neovimでの入力を妨げない）。macOSでは `NSWindow` の `orderFrontRegardless`、Linuxでは GDK のウィンドウの `raise` を使う。LinuxのWaylandでは前面に出ないことがあり、それは既知の制限としてREADMEに書く
- フロントエンドが起動時のモード（Neovim連携／スタンドアローン）を取得できるコマンドを用意する
- `mdsight_search` は、受け取ったらそのままTauriのイベントでフロントエンドへ送る。最新のものを保持し、フロントエンドが起動直後に取得するためのコマンドも用意する
- スタンドアローンモードでは、表示中の文書を開いている窓を、後から `mdsight <file>` で同じファイルを指定したときに前面に出せるようにする
  - 表示中の文書の正規化済みの絶対パスから決まる名前で、Unixドメインソケットを待ち受ける。置き場所は一時ディレクトリの下の、自分のユーザーだけが読み書きできる（`0700`）ディレクトリにする
  - 受け付ける要求は「前面に出る」の1種類だけにする。受け取ったら、最小化を解いて窓を前面に出し、フォーカスを移す。それ以外のデータは読み捨てて接続を閉じる
  - 表示中の文書が替わったら、古いソケットを消して、新しい文書の名前で待ち受け直す。その名前で別の窓がすでに待ち受けていたら、待ち受けない（文書は移る）
  - 終了するときに、自分のソケットを消す
- `mdsight <file>` は、ファイルを検証した後、切り離す前に、そのファイルのソケットへの接続を試す。つながったら前面化を要求し、既存の窓を前面に出したことを標準出力に1行書いて、ウィンドウを開かずに終了する。つながらなければ、残っているソケットのファイルを消して、いまどおり起動する
- アプリのアイコンは、ライト用（白い地）とダーク用（紺がかった黒の地）の2枚を実行ファイルに埋め込む。ライト用は `src-tauri/icons/icon.png`、ダーク用は `src-tauri/icons/icon-dark.png` に置く。元のSVG（`icon.svg`、`icon-dark.svg`）も同じディレクトリに置き、PNGは `scripts/render-icons.swift`（macOSのWebKitで描く）で書き出す
- 窓を作った直後に、OSのテーマ（`window.theme()`）に合うほうのアイコンを設定する。開発ビルドでもリリースビルドでも、同じように設定する
- フロントエンドから「ライト／ダーク」を受け取って、アイコンを差し替えるコマンドを用意する。差し替える先は、macOSでは Dock のアイコン（`NSApplication` の `setApplicationIconImage`）、Linuxでは窓のアイコンにする。LinuxのWaylandでは反映されないことがあり、それは既知の制限としてREADMEに書く

DO NOT

- ディレクトリ単位でassetプロトコルのスコープを許可しない
- Neovim連携モードでは、Markdownのファイルを読みに行かない（本文はNeovimから受け取る）

## フロントエンド（TypeScript）

DO

- 本文は `.markdown-body` 要素の中身だけを差し替える。ページ全体の再読み込みはしない
- 本文の幅は窓いっぱいに使う。左右の余白は同じにする
- 窓の一番上に、表示中の文書の絶対パスを出す帯を置く。スクロールしても上に留める
  - ホームディレクトリの部分は `~` に縮める
  - 帯に収まらないときは、左側を `…` で省略する。ホバーしている間だけ、パスを横に流して全体を見せる。`prefers-reduced-motion` のときは流さず、ツールチップで全体を見せる
  - 表示中の文書が替わるたびに更新する
  - クリックしても何もしない
- 受け取った版が、表示中の版より古ければ破棄する。非同期の処理（Mermaid、画像、KaTeX）は、完了した時点で版を確認し、古ければDOMに反映しない
- 差し替える前に「画面の上端付近にあるブロックのソース行と、画面内でのオフセット」を記録し、差し替えた後にそこへ戻す
- Mermaid：`startOnLoad: false`、`securityLevel: "strict"` を指定する。図の元のコードとテーマの組をキーにして、SVGをキャッシュする。構文エラーはそのブロック内にだけ表示し、他の部分の描画は続ける
- KaTeX：`[data-math-style]` の要素だけを描画する。`trust: false`、`throwOnError: false` を指定する。数式の元のコードをキーにして、結果をキャッシュする
- コードのシンタックスハイライト：言語名の付いたコードブロック（`mermaid` を除く）を highlight.js で色付けする。言語名がないものと、highlight.js が知らない言語は色付けしない。コードと言語名の組をキーにして、結果をキャッシュする。配色は highlight.js の GitHub 用のライト／ダークを、テーマに合わせて切り替える
- 画像：相対パスは、Rustのコマンドで解決してから `convertFileSrc` でURLに変換する。`https:` の画像はそのまま表示する。それ以外のスキームの画像は表示せず、代替テキストを表示する。生HTMLの `img` も同じにし、`source` の `srcset` の各候補も同じ規則で解決する（表示できない候補は除く）
- 生HTMLの `details`：本文を差し替えるとき、差し替える前に開いていた `details` を、出現順を手がかりに、差し替えた後も開いたままにする。ページ内検索の現在の一致が閉じた `details` の中にあれば、その `details` を開く
- リンク：`#` で始まるリンクは、ページ内でスクロールする。`http:` / `https:` のリンクは、tauri-plugin-openerで既定のブラウザを開く。相対パスで、拡張子が `md`／`markdown`（末尾に `#見出し` が付いていてもよい）のリンクは、Rustのコマンドでファイルを開かせる。開けたら、`#見出し` があればその見出しへ、なければ先頭へ移動する。それ以外のリンクは何もしない。どの場合もWebView自体は遷移させない
- 「戻る」「進む」のキー（macOSは `Cmd+[` / `Cmd+]`、Linuxは `Alt+←` / `Alt+→`）で、リンクで開いた履歴を辿る
- リンクを開くとき、戻る／進むときは、いま読んでいる位置をRustのコマンドに渡す。戻る／進むで開いた文書に、Rustから位置が返ってきたら、先頭ではなくその位置に戻す（差し替えのときと同じく、そのソース行を含むブロック、なければ直前のブロックに合わせる）。画像と図の描画が終わった時点で、もう一度同じ位置に合わせる。Neovim連携モードでは、位置を戻した文書の世代で最初に届くカーソル行には追従しない（プレビューだけ読み進めていても、Neovimのカーソル位置に引き戻さないため）。その後に届くカーソル行には、これまでどおり追従する
- 「戻る」「進む」のボタンを、パスの帯の左端に置き、その右にパスを並べる（ブラウザのアドレスバーと同じ並び）。ボタンは帯の高さに収める。辿れない方は無効にする。有効/無効は、起動時と、リンクを開いた後、戻る/進むを行った後に更新する
- 窓の下端に、横幅いっぱいの知らせの帯を重ねて表示する。Rustから知らされた問題（読み直しの失敗など）は、取り消されるまで出し続ける。相対リンクを開けなかったときと、戻る／進むに失敗したときは、その理由を数秒だけ出す。辿れる履歴が無いときの戻る／進むは、失敗として扱わず何もしない
- トラックパッドの2本指横スワイプでも、戻る／進むを行う。クリックされた位置の祖先に、横スクロールできる要素（表、コードブロック、Mermaid図など）があれば、その要素が既にスクロールの端に達しているときだけ、戻る／進むとして扱う（端に達していなければ、要素自体の横スクロールを優先する）
- 位置表：`[data-sourcepos]` の付いた要素のうち、`.markdown-body` の直下にある要素と、リストの `li` だけを対象にする。開始行の順に並べ、`{startLine, endLine, element}` の配列として保持する
- 位置表は、描画の完了時、画像の読み込み完了（`load` / `error`）時、Mermaidの描画完了時、ウィンドウサイズの変更時に作り直す
- カーソルへの追従：その行を含むブロック（なければ直前のブロック）を探す。画面内に見えていなければ、ブロックの上端が画面の上から1/3の位置に来るように、アニメーションなしでスクロールする。見えていれば、スクロールしない
  - そのブロックが位置表のコードブロック（`.markdown-body` の直下のもの。Mermaid を除く）で、行がコードの行に当たるときは、ブロックではなくその行を対象にする（行が画面内に見えていなければ、その行の上端を上から1/3の位置に合わせる）
  - コードの行とソース行の対応は、ブロックの行範囲とコードの行数から決める。行範囲がコードの行数より2行多ければ前後に囲いがあり、1行多ければ開始の囲いだけ（文書の末尾まで閉じていない）、同じなら字下げのコードブロックとする。囲いの行は、ブロックとして扱う
- 描画を待っている間に届いたカーソル位置は、最新のものだけを保持し、描画が完了してから適用する
- 修飾クリック（macOSは `metaKey`、Linuxは `ctrlKey`）を受けたら、クリックされた要素に最も近い祖先で、位置表に含まれる要素を探し、その開始行でジャンプを要求する。見つからなければ、縦方向で最も近いブロックを使う。見つかったブロックが上のコードブロックなら、クリックした位置のコードの行でジャンプを要求する。修飾クリックのときは、リンクの通常動作を止める
- 修飾キーなしのダブルクリックでも、修飾クリックと同じ手順でジャンプを要求する。ただし、リンク（`a`）、`summary`、コードブロックのコピーボタンの上のダブルクリックは除く。1回のクリックの動作（リンクを辿る、修飾クリックでのジャンプ）は変えない。ダブルクリックで単語が選ばれる動作は、そのままにする
- 描画を待っている間（受け取った版が表示中の版より新しいとき）は、修飾クリックとダブルクリックを無視する
- テーマ：`T` キーで system → light → dark の順に切り替える。選択は `localStorage` に保存する。system のときだけ、OSの設定変更に追従する。テーマを変えたら、Mermaidの図を描き直す
- テーマを適用するたび（起動時、`T` キー、system のときのOSの設定変更）に、実際に使っている色（ライト／ダーク）をRustのコマンドで知らせて、アプリのアイコンを合わせる
- 位置表の構築と、行からブロックを探す処理、コードブロックの行とソース行の対応には、vitestでテストを書く
- 検索の一致は、一致した文字を `<mark>` 要素で包んで強調する。ページ内検索とNeovimの検索とで色を分け、それぞれの現在の一致は、ほかの一致より濃い色にする。色はライト／ダークのそれぞれで用意する。Mermaidの図と数式（`[data-math-style]` の要素）の中は、どちらの検索でも対象にしない
- ページ内検索：
  - `Cmd+F`（macOS）／`Ctrl+F`（Linux）で、窓の下端に、横幅いっぱいの検索の帯を重ねて出し、入力欄にフォーカスを移す。開いているときは、入力欄の文字を選択する。知らせの帯が出ているときは、検索の帯の上に積む
  - 検索の帯には、入力欄（虫眼鏡のアイコンと件数を枠の中に含め、帯の幅いっぱいに広げる）、前／次の一致へのボタン、閉じるボタンを、この順に並べる。字体と配色はパスの帯にそろえ、入力欄とボタンは、戻る／進むのボタンと同じ塗りと角丸にする。一致がないときは前／次を無効にする
  - 開いている間は、本文の末尾を検索の帯の分だけ延ばし、最後まで帯に隠れずに読めるようにする。カーソルへの追従と現在の一致へのスクロールでは、パスの帯と検索の帯に隠れた部分を、見えていないものとして扱い、上から1/3の位置は、その間の高さで決める
  - 入力するたびに、本文の文字（コードブロック、表、フロントマターの表を含む）から、入力した検索語を、Neovimの検索と同じ書き方（Vimの正規表現）として探し、すべての一致を強調する
  - 検索語は、次の書き方に対応する（それ以外の `\` で始まる書き方と、正しくない検索語は、件数の欄に `Invalid pattern` と出し、強調を消す）。`\%V` や `\%23l` のような、エディタの状態に依存する書き方には対応しない
    - 繰り返しと選択：`.`、`*`、`\+`、`\=`、`\?`、`\{n,m}`（`\{n}`、`\{n,}`、`\{,m}` を含む）、`\{-}`（最短一致。`\{-n,m}` を含む）
    - グループと「または」：`\(…\)`、`\%(…\)`、`\|`
    - 単語の境界、行頭と行末：`\<`、`\>`、`^`、`$`
    - 文字クラス：`[…]`、`[^…]`、`\s`、`\S`、`\d`、`\D`、`\w`、`\W`、`\a`、`\A`、`\l`、`\L`、`\u`、`\U`、`\x`、`\X`
    - 一致の範囲を狭める：`\zs`、`\ze`
    - 書き方の切り替え：`\v`（very magic）、`\m`（magic、既定）、`\M`（nomagic）、`\V`（very nomagic）
    - 大文字と小文字：`\c`、`\C`。どちらもなければ、検索語に大文字が含まれるときだけ区別する（smartcase。`\` に続く文字は大文字として数えない）
  - 一致は画面とは別のスレッド（Web Worker）で探し、探している間も画面を止めない。1つのブロックを探すのに0.3秒を超えたら、そのブロックだけを飛ばし、ほかのブロックの一致は強調する。全体で2秒を超えたら、まだ探していないブロックも飛ばす。飛ばしたブロックがあれば、件数の後ろに ` (partial)` と付け（一致がなければ `Timed out`）、飛ばしたブロックの数をツールチップで出す
  - `.markdown-body` の直下の要素（位置表のブロックと同じ単位）ごとに探し、要素をまたいでは一致させない。要素の中の改行を行の区切りとして扱い、`^` と `$` は行頭と行末に一致させる。幅のない一致は強調しない
  - `Enter` で次の一致、`Shift+Enter` で前の一致へ移る（端では反対の端に戻る）。現在の一致が画面内に見えていなければ、カーソルへの追従と同じく、上から1/3の位置に来るようにスクロールする
  - 検索窓に、件数を `現在/全体`（例：`3/12`）で出す。一致がなければ `No results` と出す
  - `Esc` と閉じるボタンで検索の帯を閉じ、強調を消す
  - 本文が更新されたら、同じ文字列で探し直す。現在の一致の順番は保ち（件数を超えたら最後の一致）、スクロールはしない
  - 入力欄に入力している間は、`T` キーでテーマを切り替えない
- コードブロックのコピーボタン：
  - 描画のたびに、`pre > code` のコードブロック（Mermaid を除く）を枠の要素で包み、`pre` の `data-sourcepos` を枠に移す（位置表とスクロール同期は、枠をブロックとして扱う）
  - 枠にマウスを載せている間と、ボタンにキーボードのフォーカスがある間だけ、枠の右上にコピーのボタンを出す。コードを横にスクロールしても、ボタンは右上に留める
  - 押したら、コードの文字を `navigator.clipboard.writeText` でクリップボードに書き、2秒ほどボタンの印をチェックに変える。書き込めなかったら、理由を知らせの帯に数秒だけ出す。`navigator.clipboard` が使えなければ、止まって報告する
  - ボタンのクリックは、修飾クリックでもダブルクリックでもジャンプにしない。ボタンは、ページ内検索とNeovimの検索の対象にしない
- Vim風のキー操作：プレビューのスクロールと検索だけを動かし、Neovimのカーソルは動かさない。入力欄に入力している間は、どのキーも文字として入力する。スクロールはアニメーションなしで行う
  - `j`／`k`：本文の1行の高さ（24px）の3行分だけ、下／上へスクロールする
  - `Ctrl-d`／`Ctrl-u`：見えている高さ（パスの帯と検索の帯を除く）の半分だけ、下／上へスクロールする
  - `gg`（`g` を1秒以内に2回）／`G`：先頭／末尾へスクロールする
  - `/`：ページ内検索を開く（`Cmd+F`／`Ctrl+F` と同じ）
  - `n`／`N`：ページ内検索の次／前の一致へ移る。検索の帯を閉じていても、最後の検索語があれば、帯を開き直して（強調も付け直して）次／前の一致へ移る。最後の検索語がなければ何もしない
  - `Ctrl-f`／`Ctrl-b` は割り当てない（Linux の `Ctrl+F` はページ内検索を開くキーのため）
- Neovimの検索の強調：
  - 受け取った `mdsight_search` は、最新のものだけを保持する。対象世代と版が表示中のものと一致し、描画が終わっているときだけ適用する（描画を待っている間に届いたものは、描画が終わってから適用する）
  - 一致ごとに、その行を含むブロックを位置表から探し、そのブロックの文字の中から一致した文字列を探して強調する。同じブロックの一致は、出現順に、前の一致の後ろから探す。見つからない一致（Markdownの記号を含むものなど）は強調しない
  - `current` が真の一致は、現在の一致の色にする。スクロールはしない（位置はカーソルへの追従に任せる）
- 検索の一致を探す処理（smartcase、要素をまたぐ文字列、ブロック内での出現順の対応、Vimの正規表現の変換）には、vitestでテストを書く

DO NOT

- ブロック内での補間スクロールは実装しない（段落などは、ソース行と描画後の位置が1対1に対応しないため。コードブロックは行が1対1に対応するので、上のとおり行単位で合わせる）
- CDNからは何も読み込まない（外部から読み込んでよいのは `https:` の画像だけ）
- 修飾キーなしの1回のクリックでジャンプさせない

## CI

DO

- ワークフローは、リリース用の `.github/workflows/release.yml` と、テスト用の `.github/workflows/test.yml` の2本だけにする
- テスト用：`main` への push と、`main` に向けたPRで動かす。Linux（Ubuntu、x86_64）で、フロントエンドのテスト（`npm test`）と、フロントエンドをビルドしてからRustのテスト（`cargo test`）を実行する。どれかが失敗したら、ジョブを失敗させる
- リリース用：`v` で始まるタグを押したときに動かす。手動でも実行できるようにする
- Linux（Ubuntu、x86_64）とmacOS（IntelとApple Siliconの両方で動く1つの実行ファイル）を作る
- どちらも、フロントエンドをビルドしてから `cargo build --release` を実行する
- できた実行ファイルを `tar.gz` にまとめ、タグから作るGitHubのReleaseに添付する
- 添付する `tar.gz` の名前には版を含めない（`mdsight-universal-macos.tar.gz`、`mdsight-x86_64-linux.tar.gz`）。`releases/latest/download/` から常に同じ名前で取得できるようにする
- `tar.gz` には、実行ファイルとともに `LICENSE` と `THIRD_PARTY_NOTICES.md` を入れる
- `THIRD_PARTY_NOTICES.md` は、CIのビルドのたびに生成する。中身は、実行ファイルに含まれるRustの依存と、フロントエンドのバンドルに含まれたnpmパッケージの、名前・版・ライセンス文。生成に使う道具は版を固定して入れる。生成に失敗したら、ジョブを失敗させる
- Releaseの説明は、`CHANGELOG.md` のうちタグと同じ見出し（`## [vX.Y.Z]`）の節から作る。その節が無ければ、ジョブを失敗させる

DO NOT

- Windows向けのビルドはしない
- 署名や公証、自動更新は行わない
- GitHubが公式に出しているもの以外のActionは使わない
- 生成した `THIRD_PARTY_NOTICES.md` をリポジトリにコミットしない（古くならないように）

## Tauri の設定

DO

- ウィンドウは、1つのプロセスにつき1枚だけにする。タイトルは、Neovim連携モードでは `MdSight — Linked to Neovim`、スタンドアローンモードでは `MdSight — Read Only` にする
- CSPは、同梱したスクリプトとスタイル、Tauri IPC、assetプロトコル、`https:` の画像、`data:` のフォントと画像に限って許可する。KaTeXとMermaidの動作に必要なインラインスタイルは許可する
- `beforeBuildCommand` にフロントエンドのビルドを登録する

DO NOT

- `unsafe-eval` を許可しない（Mermaidの動作に必要になった場合は、止まって報告する）
